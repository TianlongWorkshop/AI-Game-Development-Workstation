# AI 游戏开发工作站：新工程开发总控指令

生效日期：2026-11-10。适用工程：本交付包的 Source。此前总控提示词和整改提示词不再作为本工程的实施依据；保留的产品目标在本文重新列出。旧文档保留归档，不删除历史记录。

## 一、最高目标

构建面向独立开发者和小型游戏团队的 Windows AI 游戏生产工作站。统一项目上下文、资产、任务、专业工具与模型服务。用户应能从自然语言需求走到经过检查的实际产物，并在 Blender / Unreal Engine 中继续工作。

必须持续交付可运行、可验收的软件。所有功能状态必须由真实证据产生。未接通的能力明确标记，不能用静态数字、假进度、提示成功或演示立方体代替能力。

用户此次授权从新工程重写。开发时只把旧软件和旧文档当作问题证据，不复制其业务代码、IPC、任务模型或 UI。不要删除旧安装目录、旧工程、原 .blend 或 .uproject。

## 二、已经重新确认的方向

1. 半自动 Agent：理解、规划、工具选择可以自动化；执行前可见计划。重大修改、覆盖、删除、发布、未知或超预算云端调用必须有匹配范围的人工授权。
2. Local First：文件扫描、格式处理、脚本化专业软件任务等优先本地执行；理解和生成才使用模型。
3. DeepSeek First：默认逻辑别名 `deepseek.default`，自动路由为长期目标。当前实际适配器为已核实名称和价格的 `deepseek-flash`；不能沿用过时模型名或虚构费用。
4. 桌面 UI 采用接近 Blender 的暗色工作空间：顶部切换专业工作区，左侧项目与日常入口，中间制作内容/预览，右侧属性，底部任务与日志。不要以聊天区占据全部主画面。
5. Blender 和 UE 必须能真实发现、手动绑定、启动和打开项目。编辑器进程启动成功不等于桥接连接成功。
6. 动画长期覆盖完整流程；当前未实现的动捕、骨骼编辑、IK、重定向和混合不能包装为已交付。
7. UE 蓝图必须预留严谨接口。先实现读取、变更预览、备份、授权与编译校验，再开放写入。只在存在兼容且验证通过的编辑器插件时暴露工具。
8. 模型、MCP、原生工具和专业软件适配器各自有独立职责；MCP 是工具接口，不能代替 Agent Runtime，也不是所有工具的唯一入口。

## 三、当前事实基线

本版已实现：独立桌面 UI、项目创建/打开、素材复制导入与扫描、三个程序化建模模板、Blender 子进程执行与独立校验、静态 GLB 预览、专业软件发现/绑定/启动入口、UE 项目描述只读检查、预算与加密密钥配置、任务审批与中断记录。

实机验收过的生产闭环：木箱。DeepSeek 远端调用、UE GUI 启动、其他两种模板、暂停取消和跨机安装尚未分别完成实机验收。不得修改这份事实基线为全部通过，除非补上实际证据。

## 五、执行纪律

- 先读取当前代码、验证报告和接口契约，再修改。不要按旧项目惯例猜测功能。
- 每项新增功能都要有真实入口、失败状态、可追溯输出与验收证据。
- 模型只能提出结构化计划；不允许执行模型返回的任意 shell、Python 或 JavaScript。
- 所有文件访问先规范化路径、校验真实路径和授权根；处理 junction / symlink；不能仅比较字符串前缀。
- 导入默认复制，已有文件不覆盖。创建输出使用任务 UUID 的新目录。覆盖/删除必须进入单独能力和审批模型。
- 子进程参数以数组传递、`shell:false`。只允许停止本任务拥有的子进程；超时和退出码必须写入任务。
- 成功必须有实际文件和适配器验证证据。进程异常、超时、取消、网络结果未知不能当作成功。
- 关键记录必须在执行前持久化。程序重启后，运行中和暂停中任务标记为执行中断；禁止自动重复工具调用。
- 密钥只进入系统加密存储，不能进入渲染层、日志、诊断导出、示例数据和源码。
- 云端调用显示具体发送内容、模型、费用估计和预算；未知价格、失效价格、超预算阻止调用。结果未知保留预算，不能自动重试。
- 开发中允许在独立测试项目内新建可撤销文件。不得把开发测试审批冒充用户对其真实生产项目的授权。

## 六、端到端验收

### A：游戏角色制作（后续能力）

输入需求与参考 → 判断参考不足 → 输出计划与费用 → 选择真实生成服务 → 基础模型 → Blender 几何/UV/材质处理 → 人体比例/拓扑/骨骼检查 → 工程和交付文件 → 资产登记 → 展示验收证据和未完成项。生成服务未接通时，应报告阻塞，不能改为木箱后声称角色完成。

### B：动画并导入 UE（后续能力）

动作需求 → 模型/本地工具选择 → 动作产生 → 骨骼兼容检查 → 重定向 → 预览与脚滑/穿插等质量检查 → UE 适配器导入 → 引擎侧验证。骨骼不匹配、生成失败、质量不达标、导入失败都有可见状态；回退到检查点，保留证据。

### C：修改 UE 现有项目（后续能力）

需求 → 只读项目分析 → 选择版本兼容的桥接 → 读取目标资产/代码 → 提议差异和回滚点 → 授权 → 受控修改 → 编译/验证 → 输出实际结果。没有桥接就不提供可执行修改按钮。

### D：复杂场景协同（后续能力）

拆分模型、材质、灯光、角色、动画与 UE 导入任务；共享不可变产物引用和版本；明确依赖；允许单分支失败；验收后才合并到项目。不要让一个成功分支掩盖其他分支失败。

### E：成本和本地优先

逐步声明本地工具 / DeepSeek / 专家模型及理由。计划先估算；使用缓存；未知费用暂停；超预算暂停；调用后记录 usage 和结果状态。不得偷偷替换为更贵模型。

## 七、工程里程碑

- 当前预览：运行和验证最小本地闭环。修复实际反馈，完成本机全部可执行入口验收。
- 下一可安装版本：升级受维护桌面运行时，完善持久化/单实例/大项目性能、签名/安装卸载/干净电脑检查；完成 DeepSeek 实际调用和所有本地模板验收。
- 生产扩展：引入经过验证的 3D/动画/图像提供商与 UE 插件；每条新管线有独立预算、权限、错误和质量检查。
- 高级平台：可编辑任务图、MCP 与原生插件、多人协同、资产依赖和版本追踪。只有基础生产稳定后才推进。

## 八、交付格式

每次提交提供：实际修改、可运行包、完整源码、验证记录、已知限制、后续最小任务。将未测试、测试失败、接口预留和已通过明确分开。不得用计划文档替代应完成的软件工作。
