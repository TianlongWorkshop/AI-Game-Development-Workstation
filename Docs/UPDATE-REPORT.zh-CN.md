# AI 游戏开发工作站更新报告（中文）

版本范围：公开源码预览 `2.0.0-preview.6`；现有干净安装包仍为 `2.0.0-preview.5`，后续应在源码版本稳定后重新构建安装包。

日期：2026-11-19

## 一、这次更新解决什么问题

AI 游戏开发工作站的目标不是把几个 AI 聊天窗口拼在一起，而是把游戏开发中的真实输入、专业软件、AI 建议、人工审批和最终产物放到同一条可追溯链路中。

本次公开更新重点完成了：

- 公开原创源码、Blender 桥接插件、Unreal Engine 桥接插件和中英文文档；
- 明确 3D 创作、动画、美术与材质、虚幻 5 四个独立专业工作区；
- 将图片、视频、模型、说明文字和多参考集合纳入制作画布；
- 保存来源、版本、媒体时间范围、用途标注和人工修正；
- 在 AI 执行前显示范围、差异和审批入口；
- 增加任务阶段日志、检查点、撤销导向的状态管理和输出收据；
- 接通 Blender 本地桥接和 Unreal Engine 结构检查、连接与编译日志接口；
- 把源码、测试、设计思路和能力边界放进公开仓库，避免发布一个无法审查的黑盒安装包。

## 二、实际使用了哪些技术

### 1. 桌面与业务层

- Electron Windows 桌面运行时；
- JavaScript/CJS 业务模块；
- HTML/CSS/JavaScript 工作区界面；
- 本地文件系统、项目目录和 JSON 状态文件；
- Node.js 测试运行器；
- Windows 原生文件选择、程序启动和本地路径校验。

### 2. AI 与模型路由

当前源码提供本地优先的模型规划和模型能力登记机制，能够根据任务类型选择适配器，并保留模型调用的预算和记录。

DeepSeek 连接代码已经存在，使用云端模型前会显示调用范围和费用上限。当前版本不能宣称所有常见游戏 AI 都已经完成接入，也不能把未验收的远端模型调用描述成稳定生产能力。

### 3. Blender 桥接

Blender 桥接使用本机服务和 Blender Python 扩展，提供：

- 本地连接状态；
- 场景、物体和材质相关的受控操作；
- 视口和截图信息；
- GLB/GLTF/FBX 等输出接口；
- 受控脚本和错误返回；
- 工作站与 Blender 之间的本机端口和会话信息。

工作站不会把用户的 Blender 工程偷偷上传到远程服务。用户仍然在 Blender 中完成最终编辑和检查。

### 4. Unreal Engine 5 桥接

UE 桥接位于公开源码的 `plugins/unreal/AIGWBridge/`，提供：

- 工程和编辑器连接；
- 项目版本提示；
- 蓝图结构读取和节点文本检查；
- 编译与错误日志接口；
- 后续导入、截图和编辑器动作的扩展入口。

完整蓝图图表编辑、任意节点自动生成和全部 UE 版本的二进制适配仍然需要继续开发。

### 5. 资产与媒体

当前工作站可以处理：

- 图片；
- 视频；
- GLB/GLTF/FBX/OBJ/Blend 等模型；
- Markdown、文本和代码说明；
- 项目内资产引用；
- 多参考集合和画布连线；
- 视频参考帧、时间范围和人工备注。

重要原则是“引用不等于复制”：画布会保存来源、版本和哈希，用户删除画布节点不会自动删除原始资产。

## 三、推荐使用方式

1. 启动工作站并创建或打开项目。
2. 在项目中心导入自己的图片、视频、模型和说明文字。
3. 进入对应工作区：3D、动画、美术与材质或虚幻 5。
4. 将资产拖入画布，选择用途并建立多参考集合。
5. 选中需要 AI 处理的真实节点，查看 AI 建议、范围和差异。
6. 人工修改提示、参数和连接，然后批准任务。
7. 观察阶段日志、检查点和输出分支。
8. 用 Blender 或 Unreal Engine 回读产物，确认实际结果。
9. 保存输出收据、验证结果和版本信息。

## 四、设计思路

### 人工主导、AI 辅助

用户决定使用哪些真实数据、调用哪个模型、批准哪些修改以及最终采用哪个产物。AI 不应绕过审批直接覆盖项目。

### 四个工作区独立

3D 创作、动画、美术与材质、虚幻 5 各自拥有画布和专业视图。公共能力通过明确的输入和输出连接，避免把材质节点、骨骼节点或 UE 蓝图节点混在其他工作区。

### 本地优先

资产、桥接、项目和验收尽量在本机完成。联网仅用于用户主动选择的模型、更新或授权，不能成为隐藏的远程执行通道。

### 每项能力都要有产物

功能不能只用“按钮存在”证明。需要有真实文件、日志、哈希、专业软件回读或用户可复核的差异。

## 五、技术指标与验收证据

当前测试记录包含：

- 65 项自动化测试中 64 项通过；
- 1 项 Windows 符号链接测试因当前环境没有创建符号链接权限而被阻断，业务断言本身没有执行；
- 包装测试通过，包括交付源码边界检查；
- Blender 4.4.1 实测；
- 验收网格为 38 个网格、5,286 个顶点、4,104 个三角形；
- 木箱工作流完成真实文件闭环，包含 Blend、GLB、预览图、验证结果和任务收据；
- 画布验收包含图片、视频、模型、多参考、连线、时间范围、人工修正和蓝图文本检查。

这些数字代表当前验收记录，不代表所有电脑、所有模型、所有 Blender/UE 版本都能达到固定性能。

## 六、与同类型 UeToolkit（“虚幻盒子”样本）的比较

以下比较基于本机 `UeToolkit` 3.5.0 文件和公开源码的静态分析，不能代替对方服务器、价格和实际服务条款的核验。

| 对比项 | AI 游戏开发工作站 | UeToolkit 样本 |
| --- | --- | --- |
| 核心定位 | 人工主导的 AI 游戏制作工作站 | UE 资产管理、导入和插件工具 |
| 工作流 | 真实输入 → 画布 → AI 建议 → 审批 → 专业软件 → 验收 | 资产扫描、缩略图、导入、插件安装和项目管理 |
| AI 参与 | 任务规划、模型路由、参考集合、范围和差异 | 本地样本能确认授权和资产工具，不能据此确认同等的 AI 制作链路 |
| Blender | 本地桥接和制作工作区 | 本地文件和资产工具为主，具体桥接能力需单独验证 |
| UE 兼容策略 | 当前公开 AIGW Bridge 和项目连接接口 | 样本内含 UE 5.0.3–5.8.2 多套插件构建，版本安装成熟度更高 |
| 资产包处理 | 项目资产引用、来源、哈希和工作区 | zip/7z/rar、密码凭据、缩略图和资产导入逻辑较完整 |
| 审批与追溯 | 范围、差异、任务日志、检查点、输出收据 | 更偏向资产导入和插件事务记录 |
| 开源程度 | 原创源码、桥接源码和设计文档公开 | 本地安装样本主要是打包后的 PyQt/Python 客户端，核心服务端不在本机包内 |
| 商业模式 | 当前公开源码不绑定付费服务 | 样本明确有试用、月卡、永久授权和远程授权验证 |

## 七、我们的主要优势

### 1. 面向“做东西”，而不是只管理东西

UeToolkit 样本在资产搜索、导入、缩略图和 UE 插件安装方面更成熟；我们的重点是把创作输入、AI 建议、人工审批和最终制作连接起来。

### 2. 人工审批是产品结构，不是口头承诺

每个 AI 任务都可以展示输入范围、输出分支和差异。用户可以拒绝执行，也可以回到 Blender 或 UE 中继续调整。

### 3. 来源和版本可追溯

图片、视频、模型和说明文字都保留来源、哈希、版本和用途。媒体识别结果不会自动覆盖人工修正。

### 4. Blender 与 UE 放在同一制作链路中

工作站不是只围绕 UE 资产库设计，而是同时把 Blender 建模、动画、材质和 UE 项目检查放进同一条本地工作流。

### 5. 开源和可审查

原创源码、桥接插件、测试和设计文档都可以被全球开发者检查、修改和复现。安装包和第三方依赖仍然单独说明授权边界。

### 6. 不把未完成能力包装成完成能力

当前文档明确写出蓝图图表编辑、自动蒙皮、完整 PBR 生成和任意文本到 3D 尚未完成。这有利于开发者真实参与，而不是被宣传页面误导。

## 八、UeToolkit 样本比我们更强的地方

这部分也必须公开说明：

- 多个 UE Launcher 版本的插件二进制和构建号管理更完整；
- 插件安装、备份、哈希校验和回滚流程更成熟；
- 压缩资产包、缩略图、资产库和导入事务覆盖更广；
- 试用、月卡、永久授权、离线宽限和更新服务已经产品化。

我们不应把工作站描述成已经全面替代它。更准确的定位是：工作站负责创作编排和 AI 辅助，资产管理和 UE 插件产品化能力需要继续吸收成熟经验。

## 九、当前限制与后续更新

### 当前限制

- 安装包仍是 `preview.5`，源码公开版本为 `preview.6`，需要重新构建统一版本；
- 尚未完成签名安装器和干净电脑全流程验收；
- UE 多版本二进制插件安装中心尚未达到 UeToolkit 样本的成熟度；
- 完整材质节点、蓝图图表编辑、自动蒙皮和动捕重定向仍在开发；
- 尚无大规模资产库扫描速度、并发量和显卡性能基准；
- 公开源码不包含用户项目、缓存、密钥、生成资源和第三方商业资产。

### 下一步

1. 重新构建与源码版本一致的安装包。
2. 为 Blender 和 UE 插件增加版本清单、哈希和自动安装验收。
3. 完善资产缩略图、标签、重复检测和项目级索引。
4. 增加美术与材质专属节点体系，覆盖颜色、法线、粗糙度、金属度、AO、位移、镜面、发光、遮罩和次表面散射。
5. 完善 UE 蓝图读取、连接检查、定位、编译和日志回读。
6. 在干净电脑和大型资产库上发布可重复的性能报告。

## 十、发布方式

源码仓库公开：源码、桥接、设计、测试、技术指标和中英文说明。

GitHub Release 附件：安装器、SHA-256 校验文件、变更日志和安装说明。

不公开提交：个人项目、用户素材、缓存、凭据、测试生成目录、商业第三方资产和本机路径。
